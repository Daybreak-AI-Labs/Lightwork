01 The problem

Agents are arriving from everywhere. None of them answer to the same thing.

Agentforce, Copilot Studio, the team's own builds, an open-source runtime someone stood up last quarter: each one is its own black box, with its own memory and no shared accountability.

01

No shared oversight

Each vendor's agents are governed, or not, on their own terms. There is no single place to see what the fleet did.

02

No shared memory

What one agent learns dies inside one vendor's box. The next agent re-learns it, or repeats the same mistake.

03

No per-vendor accountability

When something goes wrong, or right, you can't say which vendor's agent caused it, or what it cost.

02 How it works

Enroll, screen, record, remember: across every vendor.

One enrollment writes the agent's trust entry, its place on the memory roster and its platform provenance. From then on it runs on its own runtime, governed on yours.

01
Enroll
Register the agent with the Agent Trust Plane (direction, tool, risk and budget ceilings, expiry) and the fleet-memory roster. Who enrolled it is audited.
02
Screen
The agent asks before acting. Trust admission, the cumulative budget, Shield input scanning and the approval floor all apply.
03
Approve
A high-risk action parks a real approval that a person decides in the dashboard while the agent waits.
04
Record
Each completed run lands on the Operating Record as a goal owned by the agent, with its steps, outcome and cost.
05
Remember
Deposits and recalls go through fleet memory: roster-gated, Shield-scanned, tenant-isolated and audited.

The external boundary fails closed: an unenrolled agent is denied, a Shield scanner error denies rather than waving the action through, and an agent over its budget is refused further actions. It all runs on the dashboard server you host, self-hosted or air-gapped.

03 An audited read

Every recall is attributed, to the agent and vendor that made it.

An external agent recalls a lesson: the query is Shield-screened, the read is roster-gated and floored to the tenant, and the audit row records what was disclosed and to whom. Deposits are counted per vendor and agent, and external runs carry their cost onto the Operating Record.

04 Vendor-neutral

Govern what you already run, whoever built it.

You do not have to move your agents onto Lightwork's runtime to govern them. Enrollment, screening, the record and the shared memory work for agents that stay where they are.

01

Vendor-neutral by design

Agentforce, Bedrock Agents, Copilot Studio, OpenAI, LangChain or LangGraph, or a home-grown runtime: they all enroll, screen and remember through the same governed path.

02

One record for the whole fleet

Every read audited, every deposit attributed, every external run on the Operating Record next to native ones. The oversight you can't get from any single vendor's console.

03

Off until you decide

External agents ([external_agents] enable) and fleet memory ([fleet_memory] enable) are off by default. Opening your memory to outside agents is an explicit trust decision.

01 The problem

Agents pass the demo. They fail the diligence review.

In regulated work the blocker isn't capability. It's three questions no one can answer, so the project never leaves the pilot.

Q1

“What did it do?”

No tamper-evident record of the actions an agent took.

Q2

“Could it exfiltrate our data?”

No policy-enforced egress control, a black box, or a framework you secure yourself.

Q3

“Will it get worse?”

No way to review what it learned, or to undo a change that made it worse.

02 How it works

Not a chatbot. Not a framework. A governed runtime.

You give Lightwork a goal. An orchestrator plans the work, hands parts of it to specialist agents on the models you choose, checks their results and returns an answer. Every action along the way (every tool call, every payment, every write) passes through one gate before it happens.

01
Capability
Attenuate-only grants. A sub-agent can narrow its rights, never exceed its parent's.
02
Policy
Allow, deny, or require a human, bound to every action.
03
Shield
Scans input, every tool call and every answer for injection and dangerous actions.
04
Budget
Hard caps on dollars, wall-clock, tokens and tool calls.
05
Audit
A signed, hash-chained entry you can verify offline.

Runs on your laptop, your servers, your cloud account or a fully air-gapped network, with the same gates and your own keys. Commands run in the sandbox backend you choose; with the default local backend they run directly on the host, so use a container backend for any goal you would not run yourself.

03 The company brain

Cortex. Everything your company knows, in one governed mind.

Cortex is one governed surface over everything the agents know: your documents and data with citations, the skills learned on your work, lessons proven on held-out tasks, the Operating Record of every decision and sign-off, and what outside agents deposited. Every read is floored to the active tenant and audited, and nothing is pooled across tenants. It runs inside your own deployment.

04 Why Lightwork

Three things Lightwork is built on.

01

Governance on every action

Capability grants, a policy engine, the Shield, budget caps and a signed, hash-chained audit log you can verify offline. Deep infrastructure, not a prompt over an API.

02

Improvement you review

Learned skills and proposed changes to prompts and memory wait for a person's approval and are snapshotted so they can be rolled back. A changed specialist can run as a trial before you promote it.

03

Specialists, already built

Built-in specialist packs across finance, tax, legal, privacy, GRC, operations and more. Each declares a persona, the tools it may and may not use, a risk ceiling and a step-by-step workflow.

Invariant tests run across every specialist pack on every build: no drafting pack can reach a state-mutating tool, a pack still in onboarding never acts autonomously, a spawned agent never exceeds its parent's grant, a compartment seal never reaches another compartment, and the hard-refusal floor cannot be removed.

08 Security & deployment

Built to clear your security review.

Every control your reviewers ask about maps to a mechanism in the code, not a promise on a slide. Here is what each one does, and where it stops.

What your reviewers requireThe mechanism
Runs inside your boundarySelf-hosted or air-gapped: your machine, your servers, your cloud account, or fully offline with local models. Sensitive local stores are encrypted at rest (AES-256-GCM) by default.
Egress controlled by policyEnterprise mode pins model calls to local or self-hosted providers and checks each outbound request made through the supported HTTP clients. It is an application-layer control: pair it with sandbox network isolation and a network egress policy.
Least privilege, per actionCapability grants: with enforcement on, a sub-agent's grant is attenuated from its parent's and can never exceed it. Connector changes wait for a person's approval.
Bounded blast radiusContainer sandboxes (Docker, Podman) drop all Linux capabilities and have no network by default · hard caps on dollars, wall-clock, tokens and tool calls.
A provable, tamper-evident recordHash-chained, Ed25519-signed audit log, checked by lightwork audit verify or a standalone verifier that needs no Python.

11 Get started

Install it from source in a few minutes.

Lightwork is alpha software. No packaged release is published yet, so the supported path is a clone of the repository. You need Git and Python 3.11 or 3.12; Docker or Podman is recommended for running commands in a container.

macOS · Linuxfrom a fresh terminal
git clone https://github.com/Daybreak-AI-Labs/Lightwork
cd Lightwork
python3 -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python scripts/install_release_cohort.py --core-extra release-runtime,evidence-analysis
lightwork doctor
lightwork dashboard

lightwork doctor checks the installation and suggests a fix for anything it flags. The dashboard opens at http://127.0.0.1:8765 and walks you through first sign-in and connecting a model provider; lightwork init runs the same setup in the terminal.

Windows PowerShell commands, post-install checks and the execution posture are in the install guide.

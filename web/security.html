Security & deployment

Built to clear your security review.

Every control a reviewer asks about maps to a mechanism in code you can read, not a promise on a slide. Lightwork is self-hosted or air-gapped, with sandboxed execution, capability tokens, approvals with separation of duties, a policy on every action, an egress lock for model calls, and a signed, hash-chained audit log you can verify offline.

01 The controls

Mapped, not promised.

What a security reviewer requires, and the mechanism in Lightwork that addresses it. Some controls are on by default; the rest are switches you turn on, noted below.

What your reviewers requireThe mechanism
You decide where data is heldSelf-host or air-gap. The world model, the audit log and the keys live on infrastructure you run. Model calls go only to the providers you configure.
Model calls locked by policyEgress lock (Enterprise mode): model calls are pinned to local or self-hosted providers, and a cloud call is refused before any prompt is sent. Outbound requests made through the supported Python HTTP clients are checked against a per-tenant allow/deny policy. It is an application-layer control, not a packet firewall: pair it with sandbox network isolation and a default-deny network egress policy to cover raw sockets and subprocesses.
Least privilege, per actionCapability tokens (attenuate-only): a spawned agent's grant is narrowed from its parent's and can never exceed it. On in Enterprise mode or with MAVERICK_ENFORCE_CAPABILITIES=1.
Separation of dutiesDual control: by default the requester cannot approve their own request, and the agent can never approve its own. Require N distinct approvers globally or per risk band with [security] approvals_required.
Bounded blast radiusSandbox backends: Docker and Podman run each command in a throwaway container with all Linux capabilities dropped, a process limit and no network by default; Kubernetes, gVisor and SSH backends isolate further. The default local backend runs commands on the host, so use a container backend for untrusted goals. Hard budget caps on tokens, dollars, wall-clock time and tool calls.
A person stays in controlPolicy on every action: allow, deny, or require a human. High- and critical-risk actions require confirmation by default, and a connector change to an external system waits on the Approvals page until a person approves it.
A provable, tamper-evident recordSigned, hash-chained audit (the Operating Record): Ed25519-signed by default and verifiable offline with lightwork audit verify or a standalone Rust verifier. Export it as JSONL or ArcSight CEF for a SIEM.
Evidence on demandProof pack (python -m maverick.proof_pack): a signed evidence bundle and a PROOF.md that verify offline. A section it cannot run reports NOT RUN with the command to reproduce it, instead of a number.
Safety posture asserted in CIMachine-readable reports: lightwork safety --json prints the shield status, sandbox backend and egress policy, and lightwork airgap exits non-zero on any outbound path in the configuration.
Keys and data at restEncrypted at rest: sensitive local stores use AES-256-GCM by default, and the key can come from a KMS or secrets manager. An optional out-of-process model proxy holds provider API keys so they never enter the agent's process.
02 Governance, machine-checked

Safety you audit, not safety you trust.

Six governance invariants are tested on every CI run, the pack-level ones across every built-in specialist pack. Randomized property tests run thousands of cases, and fault-injection controls prove the pack-wide checks can fail, so a passing result can't be vacuously true. The tests are in the repository for you to read and run.

03 Deployment

Runs where your policy requires.

You run Lightwork yourself. The same gates, the same record, and your own keys, wherever you put it.

01

Your machine

Install from source and open the dashboard on 127.0.0.1. Serving it on any other address requires a dashboard token.

02

Your servers or cloud

Docker, Kubernetes with the Helm chart, or a single VPS, with SQLite or Postgres for the world model. Reference deployments are in the repository.

03

Air-gapped

Run local models through Ollama, vLLM or TGI with Enterprise mode on. lightwork airgap checks the configuration for any outbound path and exits non-zero if it finds one.

Lightwork is alpha software. No release, PyPI package or container image is published yet; install from source, and security fixes land on main. Read the execution posture before running untrusted goals.

04 Audit & evidence

Proof a reviewer can verify, offline.

The Operating Record is a signed, hash-chained log of every governed action. Each entry carries the hash of the one before it, so altering a single row after the fact breaks the chain and the verifier reports it.

operating record● chain verified
# each entry chains to the one before it
0xA2 · deny $60k wire✓ signed
0xA3 · require-human $6k✓ signed
0xA4 · cap runaway loop✓ signed
· alter 0xA2 after the fact ·✗ CAUGHT
proof pack● Ed25519 signed
# PROOF.md · verifies offline
signature✓ Ed25519
governance checks✓ PASS
benchmark without a keyNOT RUN, never filled in

One limit, stated plainly: by default the audit signing key lives on the same host, which catches accidental or unprivileged edits but not someone running as the service account. Supply the key from outside the host (MAVERICK_AUDIT_SIGNING_KEY, or a KMS-wrapped key) and publish checkpoints with lightwork audit checkpoint to an independent location to narrow that gap.

06 Report a vulnerability

Found a problem? Tell us privately.

Please don't open a public issue for a vulnerability. The full process is in SECURITY.md.

preferred

GitHub private reporting

Open the repository's Security tab and choose Report a vulnerability. Include the version or commit, reproduction steps and the impact.

otherwise

Email

If you can't use GitHub, email chris@daybreakailabs.com.

disclosure

Coordinated, and credited

A 90-day coordinated disclosure window, an advisory once a fix is available, and credit for the reporter unless you prefer to stay anonymous. There is no paid bug bounty.

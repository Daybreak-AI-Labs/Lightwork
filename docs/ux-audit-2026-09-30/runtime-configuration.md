# Saved versus running settings

All settings review labels each proposed change as immediate on the next request/policy check, next-work configuration, or requiring the owning service to restart. Each entry names before/after values (with existing secret redaction), source, organization/workspace impact and the module that consumes it. Removing one proposed entry rebuilds the review for the remaining batch and retains excluded drafts.

`maverick.runtime_configuration` captures hashes at the first global configuration read, before later services are constructed. Native dashboard, background worker, channel server and gRPC startup publish a receipt only after reaching their launch point. A heartbeat renews observation time, never the captured configuration. Stopping removes that instance's receipt; an abrupt stop becomes stale after 100 seconds. Metadata is encrypted using the existing at-rest policy, owner-only and retained at most seven days. It contains configuration/environment hashes, never setting values or credentials.

The global-admin `/api/v1/settings/runtime-status` projection compares each requested setting and its environment overrides against fresh receipts from the appropriate consumer. Missing, unreadable, stale, tenant-scoped or mismatching consumers stay unconfirmed or pending. Dashboard restart cannot confirm channel-server changes. The global Settings screen displays saved and startup revision evidence without reloading editors, restarting services, or dispatching work. The scope statement is deliberate: these receipts cover observed processes using this configuration directory, not a remote unobserved fleet, and startup configuration is separate from service health or task outcomes. gRPC launches with explicit runtime arguments are excluded from configuration acknowledgement.

Control `[settings] runtime_status = false` in All settings or the installer to disable reporting; it does not affect settings persistence or startup. The same installer checkpoint adds default-on `features.employee_task_diagnostics` and `features.employee_activation` for their owned employee journeys.

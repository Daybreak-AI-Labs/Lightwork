# Knowledge feedback through Copilot

Open an authorized source's **Details** in Knowledge, then choose **Report an exact source correction or concern** in Copilot. Review the request type, business reason and proposed correction before confirming. **Review my knowledge requests** shows the latest 100 requests from the current named account and workspace. It does not expose another requester's reason, source dependency analysis or preservation holds.

This uses the existing Knowledge feature, native operate permission and existing optional Copilot **learning** family. It rechecks the exact source version and permitted use during preview and execution. Changing source, workspace or access invalidates the review. Native request-key idempotency prevents duplicate submissions; a revoked source must be reopened under current authority, while the separate own-status action remains available for its retained request.

The adapter always uses employee feedback intake, including for administrators. It cannot approve/apply a source change, grant deletion or training authority, or release a hold. Those remain separately governed native review workflows. Confirmation requires a durable matching request and its audit receipt; otherwise the outcome remains unconfirmed.

Local validation used real local-owner cookies, workspace selection, exact registry references and the native request service with synthetic source/rights adapters. It proves source revocation before execution, workspace-switch refusal, duplicate identity, independent status ownership and unchanged approved source state. No external provider or production system was called.
